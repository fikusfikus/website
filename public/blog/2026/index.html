tmux configuration

2026-09-16

I’m pretty much making this post just to have some test content for the blog section of my site lol.

It’s pretty rare that I have to reconfigure tmux since I usually just hang onto the same dot files forever, but it is always kind of a pain in the ass so I may as well log it here for future reference. I’ve been planning on making a new website with the static site generator “Hugo” for a bit now. I’ve been maining a hackintosh since ~2018 and for the past few years I’ve just been letting it fall apart. I knew hackintosh was gonna die some day and since I generally refuse to update my OS ever if possible, I couldn’t update the “command line tools” to install Hugo without updating the whole damn OS. I decided to say fuck it and just install Linux and Windows on some dual boot type shit. So now after about a week copying multiple TBs of data from APFS > ExFat > NTFS and configuring Debian-stable (I will avoid updating my shit at all costs), I’ve finally got Hugo going. I use vim as my main text editor because I want to pretend I know what I’m doing, so this means getting tmux to stay organized while I mess with Hugo. To avoid putting my NVME drive with hackintosh installed back into my PC to fetch my old tmux config, I decided to just make a new one. My last tmux config I made in probably 2014 was likely a mess of other people’s configs spliced together. I’m starting fresh and haven’t made a tmux config in a while, so why not.

# remap prefix
unbind C-b
set-option -g prefix C-a
bind-key C-a send-prefix

This just gives you the classic “screen” prefix, control+a. I don’t know who likes reaching for control+b everytime but it’s not me. I always kind of figured they just picked it alphabetically after screen took a. Fun, but useless to me.

# bind r to reload config
bind r source-file ~/.tmux.conf \; display "config reloaded"

A big part of my efforts here is just to get the theme looking decent. Control+a - r is a much better way to quickly test changes vs typing tmux source-file ~/.tmux.conf every time.

# allow graphics passthrough to kitty
set -g allow-passthrough on

Took me a while to figure this one out when trying to get my mpd album art script working.

Here’s all the other non-theme bullshit:

# remap the rename session bind
unbind $
bind s command-prompt -I "#S" "rename-session '%%'"

# dont ask for confirmation when killing a pane
unbind x
bind x kill-pane

# make windows start with 1 instead of 0
set -g base-index 1
setw -g pane-base-index 1

# renumber windows when closing one - ABCD, delete C, = ABC
set -g renumber-windows on

# new windows take the current path instead of home
bind c new-window -c "#{pane_current_path}"

# self explanatory stuff
set -g mouse on
set-option -g history-limit 5000
bind space last-window

Alright, now onto the point. Setting the theme up to be something simple and readable is always the most annoying part.

# global status bar options
set -g status-style bg=default
set -g status-style fg=default
set-option -g status-justify centre

# left status bar options
set-option -g status-left "  #S"
set-option -g status-left-style "dim"

# window list options
set -g window-status-format "#I #W"
set -g window-status-style "nobold,dim"
set -g window-status-current-format "#I #W"
set -g window-status-current-style "bold"
set -g window-status-separator "   "

# right status bar options
set-option -g status-right "local  "
set-option -g status-right-style "dim,fg=4"

# message colors
set -g message-style "fg=default,bg=default"

# pane border colors for splits
set -g pane-border-style fg=7
set -g pane-active-border-style fg=7

This is all it takes for me. It looks like this:

The small local in the corner there is hardcoded from status-right "local ", and all that does is pretty much tell me that this tmux session is not in ssh. I have a copy of this config on my VPS where it’s set as vps instead, etc. The blog on the left there is just what I’ve named the session with control+a - s.
